# HN Effective Dashboard

Проект сбора и обработки данных для построения Power BI дашборда (9 страниц отчёта) по HR-метрикам H&N.

## Источники данных

| Источник     | Папка                  | Описание                        |
|--------------|------------------------|---------------------------------|
| ОЭД          | data/raw/oed/          | Оценка эффективности деятельности |
| ОКК          | data/raw/okk/          | Отдел контроля качества         |
| Обучение     | MariaDB корпоративного университета | Курсы, прогресс и результаты тестов |
| KPI план/факт | data/raw/kpi/fact kpi/ | Клиентские планы и факты PICOS, OSA и TOP16 |
| Визиты KPI   | data/raw/kpi/sql_exports/ | Пакеты из клиентской SQL: визиты, сотрудники и ТТ |
| USERS        | MariaDB корпоративного университета | Пользователи, сотрудники и руководители |
| Кадровые файлы | data/raw/users/      | Вакансии, кадровый реестр и текущая привязка ТТ к ТМ |
| ENPS         | data/raw/enps/         | eNPS опросы                     |
| АТТЕСТАЦИИ   | data/raw/attestations/ | Аттестации сотрудников          |

## Структура проекта

```
config/                — настройки (settings.yml) и справочники (карта регионов, карта колонок ОКК)
data/raw/               — исходные файлы по источникам (не в git)
data/out/               — готовые витрины (parquet) для Power BI (не в git)
docs/                    — итоговая методология, формулы и материалы для презентации
scripts/
  parsers/               — парсеры исходных источников (7 основных + вакансии/кадровый реестр)
  builders/               — сборка витрин для страниц Power BI (build_page1…9) и справочников
  tools/                  — вспомогательные утилиты (аудит витрин, генерация методологии)
  utils.py, staffing_utils.py — общие функции, используемые парсерами и сборщиками
  run_all_parsers.py     — главный оркестратор пайплайна (25 шагов)
tests/                    — тесты
```

## Запуск

```powershell
# Активировать окружение
.\.venv\Scripts\Activate.ps1

# Запустить весь пайплайн (все парсеры + все витрины для Power BI)
python main.py
```

При ошибке шаг фиксируется в сводке, а итоговый процесс завершается с ошибкой. Такой результат
нельзя публиковать в Power BI: старые файлы в `data/out` не считаются успешным обновлением.
# Корпоративный университет

Пользователи и обучение загружаются напрямую из MariaDB через системный DSN
`HN_Corporate_University`. Пароль хранится в Windows Credential Manager и не
сохраняется в файлах проекта.

Однократное сохранение пароля:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage_corporate_university_credential set
```

Проверка пароля и подключения:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage_corporate_university_credential status
.\.venv\Scripts\python.exe -m scripts.manage_corporate_university_credential test
```

Запуск из PowerShell в VS Code:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_all_parsers
```

После сохранения ETL запускается без повторного ввода пароля. Хранилище относится
к текущей учётной записи Windows. Файлового резервного источника нет: ошибка
подключения останавливает обновление пользователей и обучения.

## Клиентская SQL

Новые визиты и сотрудники загружаются из проверенных пакетов
`data/raw/kpi/sql_exports/HN_KPI_YYYYMM.zip`. Если пакет месяца присутствует, он
полностью заменяет RTM и файлы логинов за этот месяц. Excel RTM и логины используются
только как зафиксированная история для месяцев, по которым SQL-пакета ещё нет.

Планы и факты PICOS, OSA и TOP16 пока загружаются из клиентских файлов
`data/raw/kpi/fact kpi`. В SQL не подтверждено однозначное соответствие целевых
значений OSA и TOP16, поэтому ETL не подменяет их расчётными аналогами.

Сотрудник SQL-визита определяется по справочнику корпоративного
университета: сначала по полному ФИО, затем по единственной однозначной паре
«фамилия + имя». Неоднозначные совпадения не принимаются. ТМ определяется по
актуальной привязке ТТ и только среди активных руководителей; визит без подтверждённого активного ТМ исключается и
попадает в аудит.

## Обновление через корпоративный VPN

Учётные данные Cisco VPN хранятся только в Windows Credential Manager. При первой
настройке или смене пароля выполните в PowerShell из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage_vpn_credential set
```

Для полного обновления данных одной командой:

```powershell
.\scripts\refresh_dashboard_data.ps1
```

Сценарий проверяет доступность MariaDB, при необходимости подключает Cisco VPN,
запускает транзакционный ETL с QA и отключает только созданное им VPN-подключение.
Если VPN был подключён до запуска, сценарий не отключает его.
