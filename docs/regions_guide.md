# Нормализация регионов для Power BI

## Что нашлось в витринах

Сейчас регион приходит в нескольких форматах одновременно:

- английские коды: `MOSCOW`, `SOUTH`, `WEST`
- английские названия: `Moscow`, `South`, `West`
- русские макрорегионы: `Москва`, `Юг`, `Северо-Запад`
- локальные/ошибочные значения: `Мск`, `Юфо`, `Поволжье`, `Восток Picos`
- слишком детальные значения: `Санкт-Петербург`, `Владимирская Область`, `Краснодарский Край`

Из-за этого фильтры и сравнение между витринами ломаются.

## Итоговый справочник

Готовый маппинг лежит в `config/region_map.csv:1`.

Рекомендованный канонический список регионов:

- `Москва`
- `Юг`
- `Сибирь`
- `Волга`
- `Северо-Запад`
- `Урал`
- `Центр`
- `Дальний Восток`

## Важные решения

- `Москва и МО` и `Московская область` сведены в `Москва`
- `Санкт-Петербург` сводится в `Северо-Запад`
- `Краснодарский Край` сводится в `Юг`
- `Владимирская Область` сводится в `Центр`
- `Rsd East`, `Восток`, `Восток Picos`, `Дальний восток` сведены в `Дальний Восток`

## Как внедрить в Power BI

### Вариант 1 — правильно, через Power Query

1. Загрузи `config/region_map.csv`
2. Назови запрос `region_map`
3. В каждой таблице с регионом сделай merge по исходному полю `Регион`
4. Раскрой `canonical_region`
5. Переименуй его в `Регион BI`

Таблицы для merge:

- `dim_employees`
- `dim_teams`
- `kpi_fact`
- `okk_fact`
- `enps_fact`
- `fact_адаптация`
- `витрина_адаптации`

Для `fact_oed` и `learning_fact` регион лучше тянуть через связь с `dim_employees`.

### Вариант 2 — быстро, через DAX

Если надо прямо сейчас и без Power Query, сделай calculated column:

```DAX
Регион BI =
SWITCH(
    TRUE(),
    [Регион] IN {"MOSCOW", "Moscow", "Москва", "Москва и МО", "Московская область", "М", "Мск"}, "Москва",
    [Регион] IN {"SOUTH", "South", "Юг", "Юфо", "Краснодарский Край"}, "Юг",
    [Регион] IN {"SIBERIA", "Siberia", "Сибирь"}, "Сибирь",
    [Регион] IN {"VOLGA", "Volga", "Волга", "Поволжье"}, "Волга",
    [Регион] IN {"WEST", "West", "Запад", "Северо-Запад", "Северо-западный регион", "Санкт-Петербург"}, "Северо-Запад",
    [Регион] IN {"URAL", "Ural", "Урал"}, "Урал",
    [Регион] IN {"Центр", "Владимирская Область"}, "Центр",
    [Регион] IN {"Дальний Восток", "Дальний восток", "Rsd East", "Восток", "Восток Picos"}, "Дальний Восток",
    BLANK()
)
```

## Что делать с пустыми значениями

Сейчас есть `NULL` в `dim_employees`, `dim_teams`, `fact_адаптация`, `витрина_адаптации`.

Рекомендация:

- в BI вывести их как `Не определён`
- в отдельной карточке или QA-таблице контролировать количество таких строк

Пример DAX:

```DAX
Регион BI (с пустыми) =
COALESCE([Регион BI], "Не определён")
```

## Что я советую для первой страницы

Для первой страницы используй именно `Регион BI`, а не исходный `Регион`.

Если хочешь строго повторить макет с 6 строками, можно отдельно обсудить бизнес-правило:

- оставлять `Урал` и `Дальний Восток` как отдельные регионы
- или укрупнять их в существующие макрорегионы

Пока такого правила в данных нет, поэтому безопаснее оставить их отдельными.
