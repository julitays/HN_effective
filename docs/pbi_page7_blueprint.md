# Power BI: blueprint страницы ТМ

## 1. Что уже сделано в ETL

- собрана компактная витрина `page7_tm_monthly_snapshot.parquet`
- собран справочник `dTM.parquet`
- собрана таблица легенды расчёта `page7_tm_score_composition.parquet`
- структура ТМ, регионов, СВ и МЕ берется строго из актуального `USERS/dim_teams`
- активный периметр обучения берется из `USERS`: сотрудник входит в H&N, если `Проект = H&N` или в `Группы` есть `H&N`
- кадровые события по уволенным сотрудникам матчятся на весь `USERS`, включая неактивных, но актуальный ТМ подтверждается только текущей структурой
- личное обучение ТМ считается от всех обязательных курсов каталога: план = все обязательные курсы, факт = закрытые курсы к выбранному месяцу

## 6. Методология

`Балл эффективности %` считается прямой формулой:

- `30%` — `KPI месяца территории %`
- `20%` — `Качество команды %`
- `15%` — `Обучение команды %`
- `15%` — `Фрод %`
- `15%` — `Стабильность команды %`
- `5%` — `Текучесть %`

Логика балла:

- если метрика в красной зоне, балл за ее вес = `0`
- для метрик “чем выше, тем лучше” балл = `вес * MIN(значение / зеленый порог, 1)`
- для метрик “чем ниже, тем лучше” зеленая зона дает полный вес, желтая зона линейно снижает вес до `0` на красном пороге
- если второстепенная метрика отсутствует, ее вес перераспределяется между доступными метриками
- `KPI месяца территории %` и `Качество команды %` — обязательные ключевые метрики; без них статус = `Недостаточно данных`

Кадровые поля:

- `Стабильность команды %` = `1 - 70% * Доля вакансий % - 20% * Текучесть % - 10% * чистый отток`
- `Текучесть %` = `Уволено / Размер команды`
- `Доля вакансий %` = `Открытых вакансий / (Размер команды + Открытых вакансий)`
- если доступно меньше `60%` веса показателей, ставится `Недостаточно данных`
- структура не восстанавливается из KPI/OKK/OЭД, только из актуального `USERS`

---

## 7. Пороги статуса

- `Стабильно` — данных достаточно и `Балл эффективности >=80%`
- `Зона риска` — итоговый балл `<80%`
- `Недостаточно данных` — не хватает веса показателей для честного расчёта

Зоны метрик:

- `KPI месяца территории %`: красный `<90%`, желтый `90–95%`, зеленый `>=95%`
- `Качество команды %`: красный `<70%`, желтый `70–80%`, зеленый `>=80%`
- `Обучение команды %`: красный `<90%`, желтый `90–95%`, зеленый `>=95%`
- `Фрод %`: зеленый `<=10%`, желтый `10–18%`, красный `>18%`
- `Стабильность команды %`: красный `<90%`, желтый `90–95%`, зеленый `>=95%`
- `Текучесть %`: зеленый `<=10%`, желтый `10–15%`, красный `>15%`

---

## 8. Важные правила

- `Фрод` — количество фрод-кейсов, `Фрод %` — доля фрод-визитов
- `Размер команды` = активные МЕ + активные СВ из актуального `USERS`
- `Нанято` и `Уволено` считаются из кадрового факта за выбранный месяц
- `Нанято без ТМ` и `Уволено без ТМ` попадают только в строку `Вакансия / нет ТМ`
- `Обучение ТМ %` не участвует в `Балл эффективности %`; это личная диагностическая метрика
- `Обучение команды %` считается накопительно на выбранный месяц по СВ и МЕ из команд ТМ: все обязательные курсы, назначенные до выбранного месяца, и все курсы, завершенные к выбранному месяцу
- `Причина статуса ТМ` = список только красных флагов через запятую; возможные метрики: `KPI месяца территории`, `Качество команды`, `Обучение команды`, `Фрод`, `Стабильность команды`, `Текучесть`
- если красных флагов нет, но есть желтые зоны, `Причина статуса ТМ` остается пустой
- если все метрики зеленые, пишется `Все метрики выше целевого уровня`
