# Политика fallback-правил

Дата фиксации: 2026-09-01.

## Запрещено

- KPI нельзя рассчитывать из заменителей. Если клиентского KPI нет, значит KPI нет.
- Нельзя создавать синтетические ID сотрудников, супервайзеров или территориальных менеджеров.
- Нельзя сопоставлять людей по короткому ФИО или ФИ без отчества, кроме двух явно согласованных правил: поля `TM Name` в текущей привязке ТТ и уникальной пары «фамилия + имя» агента клиентской SQL.
- Нельзя определять компетенцию курса по словам в названии курса.
- Нельзя подставлять дату маршрута RTM вместо фактической даты визита.
- Нельзя превращать пустой флаг RTM в `False`.

## Разрешено

- `Вакансия / нет ТМ`, если в согласованном источнике структуры у СВ нет действующего ТМ.
- `Вакансия / нет СВ`, если в согласованном источнике структуры у МЕ нет действующего СВ.
- ТМ торговой точки берётся только по точному `Ship To` из `users/Привязки ТМ`.
- Короткое имя из `TM Name` подтверждается только при единственном точном совпадении фамилии и имени с активным ТМ в `USERS`; неактивные ТМ не используются.
- Если в текущей привязке у ТТ пустой ТМ, разрешено восстановление только по однозначной связи текущего кода СВ с ТМ внутри того же файла.
- Если ТМ из привязки неактивен, разрешено восстановление только по активной цепочке конкретного сотрудника `RTM → логины → USERS`.
- Для агента клиентской SQL сначала используется точное полное ФИО из `USERS`. Если полного совпадения нет, допускается только единственная пара «фамилия + имя» среди пользователей; неоднозначное совпадение остаётся пустым. Исторический визит уволенного сотрудника сохраняется как факт прошлого периода, но уволенный сотрудник не используется для назначения действующего руководителя.
- `Недостаточно данных`, если доступно меньше 60% веса согласованных метрик.
- `Мало данных`, если для адаптации новичка нет обязательного обучения или ОКК первого/второго месяца.

## Периодические метрики

- ОЭД переносится только внутри своего квартала.
- eNPS переносится только внутри года опроса.

## Месяц без клиентского KPI

- Отсутствие клиентского KPI не удаляет месяц из дашборда.
- Месяц отображается, если за него есть ОКК или кадровый срез; KPI, PICOS, OSA и TOP16 остаются пустыми.
- KPI прошлого месяца, средний KPI и расчётный аналог не подставляются.
- Статус считается только по доступным согласованным метрикам; при доступности менее 60% ставится `Недостаточно данных`.
- На странице торговых точек ТТ с проверкой ОКК сохраняется без KPI и RTM; визиты, KPI и сложность не восстанавливаются расчётным способом.

## Визиты RTM и клиентской SQL

- Визит без фактической даты визита удаляется из аналитических витрин.
- Визит с пустым флагом выполнения или подтверждения удаляется из аналитических витрин.
- Единственным источником визитов является клиентская SQL. Excel RTM и файлы логинов не участвуют в ETL и не используются как резервный источник.
- Уволенные и иные неактивные пользователи не используются для назначения сотрудника или руководителя.
- Визит исключается, если после всей согласованной цепочки не найден активный ТМ; количество исключений сохраняется в аудите.
- Соседние месяцы, город, `BU+SG` и историческая KPI-иерархия не используются для назначения ТМ.

## Источники KPI

- Excel `fact kpi` определяет назначенный торговой точке тип KPI.
- PICOS план, факт и выполнение берутся только из клиентской SQL по конкретному визиту. Excel PICOS не используется как резервный источник.
- OSA и TOP16 план и факт берутся из Excel `fact kpi`, пока их клиентская SQL-методология не подтверждена.
- Выполнение каждого KPI равно `факт / план`: ниже 75% результат обнуляется, выше 100% ограничивается значением 100%.
- SQL-PICOS точки, которой Excel не назначил PICOS, не используется и не меняет её схему KPI.
- Если точке назначен PICOS, но SQL-визит не содержит PICOS, результат этого визита остаётся пустым; OSA или TOP16 вместо него не подставляются.

## Компетенции

- В обучение попадают только курсы, присутствующие в официальном маппинге курсов.
- Компетенция курса берётся только из согласованного маппинга, без эвристик по названию.
- Для визуальных блоков допускается только точное соответствие поля `Уточнённая компетенция для ROI` короткому блоку отчёта.
