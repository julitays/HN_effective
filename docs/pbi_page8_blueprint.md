## 6. Логика ETL

- `page8_learning_course_summary`:
  - уровень `месяц назначения + курс`
  - база сотрудников = активные H&N МЕ из `dim_employees`
  - сотрудник попадает в месяц, если:
    - `Активен = True`
    - `Проект = H&N`
    - должность содержит `Мерч`
    - `Дата приёма < первый день следующего месяца`
  - источник маппинга курсов:
    - `config/courses_catalog_ЛМ_ROI_пример.xlsx`
    - лист `Лист1` → `Какую компетенцию развивает`
    - лист `ROI_карта_курсов` → `Уточнённая компетенция для ROI`
  - `Покрытие %` = доля завершенных назначений курса
  - `Тест %` = средний тестовый балл по курсу
  - окно оценки эффекта строится так:
    - `ОКК до` / `KPI до` = предыдущий месяц относительно месяца прохождения курса
    - `ОКК после 30` / `KPI после 30` = текущий месяц прохождения курса
    - `ОКК после 60` / `KPI после 60` = следующий месяц после прохождения курса
  - `Эффект ОКК %` = средний ОКК через `60 дней`, а если следующего месяца ещё нет — через `30 дней`, минус `ОКК до`
  - `Эффект KPI %` = средний KPI через `60 дней`, а если следующего месяца ещё нет — через `30 дней`, минус `KPI до`
  - `Эффект` = комбинированный эффект:
    - `65%` вес `KPI`
    - `35%` вес `ОКК`
    - если доступна только одна метрика, берется она
  - `Статус`:
    - `подтвержден` / `умеренный эффект` / `эффект не подтвержден` / `отрицательная динамика` — если уже есть окно замера
    - `в процессе замера` — если курс слишком свежий и окна после обучения ещё нет
    - `недостаточно данных` — если не хватает базы даже для старта замера

- `page8_learning_effect_trend`:
  - три точки по месяцу:
    - `До` = предыдущий месяц
    - `После 30 дней` = текущий выбранный месяц
    - `После 60 дней` = следующий месяц
  - отдельно по `ОКК %` и `KPI %`
  - содержит `MonthStart`, чтобы фильтроваться от `dMonth` так же, как остальные листы

- `page8_learning_employee_matrix`:
  - уровень `месяц + сотрудник`
  - база сотрудников = активные H&N МЕ из `dim_employees`
  - сотрудник попадает в месяц, если `Дата приёма < первый день следующего месяца`
  - вся оргструктура берется строго из актуального `USERS` через `dim_teams`
  - `Регион BI`, `Территориальный менеджер`, `СВ` = актуальная привязка из `dim_teams`
  - если в `USERS` у сотрудника нет актуальной привязки к ТМ, ставится `Вакансия / нет ТМ`
  - KPI, OKK и обучение используются только как метрики, а не как источник структуры
  - компетенции больше не определяются по ключевым словам
  - закрытие компетенций строится по явному маппингу курсов из файла `config/courses_catalog_ЛМ_ROI_пример.xlsx`
  - в текущей витрине на матрицу выведены такие зоны:
    - `Фотоаудит`
    - `PICOS`
    - `Доступность`
    - `Антифрод`
    - `Работа с ТТ`
    - `Базовые стандарты`
  - по каждой ключевой компетенции:
    - `1` = компетенция закрыта
    - `0` = пока не закрыта
  - `Закрыто компетенций` = сколько из 6 компетенций закрыто
  - `% закрытых компетенций` = доля закрытых компетенций сотрудника
  - `Незакрытая компетенция` = первая незакрытая зона

---

## 7. Что важно

- это первая рабочая ETL-версия листа
- база листа строится строго от актуальных `USERS`, а не от `page3`, KPI, OKK или истории ОЭД
- `Эффект` считается по доступной истории МЕ в `page3_merch_monthly_snapshot`, но только для сотрудников из активной базы `USERS`
- если по курсу не хватает истории после прохождения, `Статус` может быть `недостаточно данных`
- март `2026` уже есть в `page8_learning_course_summary` и `page8_learning_effect_trend`; если верхние визуалы пустые, проблема уже не в ETL, а в связи/обновлении модели Power BI
- heavy DAX для листа не нужен
