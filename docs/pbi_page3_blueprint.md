## 6. Логика ETL

- база страницы строится от активных МЕ с данными `kpi_fact` / `okk_fact` / `learning_fact`
- вся оргструктура МЕ (`Регион BI`, `СВ`, `ТМ`) берется строго из актуального `USERS/dim_teams`
- `Стаж МЕ, мес.` берется из актуальной базы `USERS/dim_employees`
- `OSA`, `PICOS`, `ОКК`, `Фрод` подтягиваются из `okk_fact` только как метрики, не как источник структуры
- `Обучение %` считается как накопительный срез обязательных курсов на выбранный месяц
- `Личная эффективность МЕ %` считается как фиксированный индекс без переразвешивания пропусков:
  - `KPI проекта %` — `40%`
  - `ОКК %` — `15%`
  - `Обучение %` — `20%`
  - `Аттестация клиента %` — `25%`
- в расчет строки месяца входят:
  - `KPI проекта %` — результат мерчендайзера за этот месяц
  - `ОКК %` — результат проверок ОКК за этот месяц
  - `Обучение %` — обязательное обучение, закрытое на выбранный месяц
  - `Аттестация клиента %` — последняя доступная клиентская аттестация на выбранный месяц
- формула индекса считается по каждому блоку отдельно:
  - если значение ниже желтого порога, блок дает `0` баллов
  - если значение достигло желтого порога, блок дает `Вес * MIN(Значение / Зеленый порог, 1)`
  - итог: сумма баллов по четырем блокам
- если по `KPI проекта %`, `ОКК %` или `Обучение %` нет данных, блок дает `0` баллов; веса не перераспределяются
- если `Аттестация клиента %` отсутствует, блок считается нейтральным: балл не снижается
- при отсутствующей `Аттестация клиента %` статус считается по остальным метрикам; если других просадок и пропусков нет, статус = `Соответствует роли`, причина = `Новичок`
- высокий личный статус возможен только при наличии `KPI проекта %`, `ОКК %`, `Обучение %` и `Аттестация клиента %`
- для `KPI проекта %`, `Обучение %`, `Аттестация клиента %`: красная зона `<90%`, желтая `90–95%`, зеленая `>=95%`
- для `ОКК %`: красная зона `<40%`, желтая `40–60%`, зеленая `>=60%`
- `Высокая личная готовность` = все 4 блока есть, индекс `>=90%`, все блоки в зеленой зоне
- `Соответствует роли` = индекс `>=80%`, нет красных зон
- `Зона развития` = индекс `<80%` или есть хотя бы один красный блок
- `Недостаточно данных` = доступно меньше `60%` веса метрик или нет `KPI проекта %` / `ОКК %`
- `Аттестация клиента Q4 2025 %` и `Аттестация клиента Q1 2026 %` подтягиваются из клиентских аттестаций отдельными колонками для сравнения периодов
- старая клиентская аттестация не участвует в причине, если актуальная клиентская аттестация уже в норме
- `Причина личной эффективности` перечисляет коротко только западающие блоки, например `Обучение, Аттестация клиента Q1 2026`
- `Аттестация клиента %` выводится в `Причина личной эффективности` только если результат ниже `90%`
- отсутствие клиентской аттестации само по себе не пишется как просадка; если остальные метрики в норме, причина = `Новичок`
- если сотрудник не начинал клиентскую аттестацию или в LMS стоит технический `0%`, в витрине остается пустое значение, а не `0%`
- `Риск ухода региона %` подтягивается из квартального `enps_fact` как контекст региона
- `Сложных ТТ` сейчас считаются как количество проблемных визитов мерчендайзера за месяц
- `Сложность ТТ` считается в ETL по методологии страницы:
  - `35%` — повторяемость проблем ТТ по истории
  - `25%` — нестабильность `OSA/PICOS` по истории
  - `20%` — повторяемость нарушений `ОКК`
  - `10%` — отклонения по полке
  - `10%` — нестабильность маршрута / смена МЕ на ТТ
- `Сложных ТТ` = количество ТТ мерчендайзера в месяце, где `Сложность ТТ score >= 45`
- `Сложные ТТ` используются как контекст среды работы, но не штрафуют `Score` и не влияют напрямую на `Статус профиля`
- `Score` = `Балл личной эффективности`, считается по согласованной формуле `KPI / ОКК / Обучение / Аттестация клиента`
- `OSA`, `PICOS`, `Фрод` остаются отдельными диагностическими метриками и не входят в `Score`
- если по блоку личной эффективности нет данных, он даёт `0` баллов; веса не перераспределяются
- `Статус профиля`:
  - считается только по `KPI`, `ОКК`, `Обучение`, `Фрод`
  - `Сильная практика` — все 4 показателя проходят пороги
  - `Требует вмешательства` — 2 и более провала по этим 4 показателям
  - `Контроль` — все остальные случаи
- `Комментарий аналитика`:
  - коротко объясняет 1-2 ключевые причины для разбора
- `Ранг` считается как dense-rank по `Score` внутри месяца

## 7. Что важно

- `Риск ухода региона %` — это именно региональный контекст, не риск конкретного мерчендайзера
- правая карточка должна фильтроваться кликом по строке в левой таблице
- отдельный сложный DAX для ранжирования не нужен
