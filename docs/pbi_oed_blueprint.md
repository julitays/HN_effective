# Power BI: blueprint страницы «ОЭД»

## 1. Что подключать

- `oed_quarterly_snapshot` → `data/out/oed_quarterly_snapshot.parquet`
- `dQuarter` → `data/out/dQuarter.parquet`
- `dRegion` → `data/out/dRegion.parquet`
- `dSupervisor` → `data/out/dSupervisor.parquet`
- `dTM` → `data/out/dTM.parquet`

---

## 2. Связи

- `dQuarter[QuarterStart]` `1:*` `oed_quarterly_snapshot[QuarterStart]`
- `dRegion[Регион BI]` `1:*` `oed_quarterly_snapshot[Регион BI]`
- `dSupervisor[ID супервайзера]` `1:*` `oed_quarterly_snapshot[ID супервайзера]`
- `dTM[ID территориального менеджера]` `1:*` `oed_quarterly_snapshot[ID территориального менеджера]`

Если связь с `dSupervisor` мешает из-за фильтров по сотруднику, можно оставить фильтрацию через поля самой витрины: `Супервайзер`, `Территориальный менеджер`, `Регион BI`.

## 6. Логика ETL

- база витрины — только активные сотрудники `H&N` из актуальных `USERS`
- орг-привязки берутся строго из актуальных `dim_teams`, `dSupervisor`, `dTM`
- источники ОЭД используются только для показателей ОЭД, но не для региона, СВ, ТМ или размера команды
- если в `USERS` нет актуальной привязки к ТМ, используется `Вакансия / нет ТМ`
- `Личная эффективность ОЭД %` = среднее доступных личных компонентов: `KPI`, `Стандарты`, `Продукт`, `Управление`, `Аттестация`
- `Команда ОЭД %` — исходное поле ОЭД для СВ, не количество людей
- командные показатели СВ считаются по активным МЕ, привязанным к СВ в актуальной оргструктуре
- `Рейтинг ОЭД` и `Класс ОЭД` не пересчитываются, а берутся из источника
